# 낙서한판

**팀 그려조**의 네트워크프로그래밍 텀프로젝트입니다.

낙서한판은 Java TCP 소켓과 Swing을 활용한 실시간 그림 퀴즈 게임입니다. 출제자가 그림을 그리면 같은 게임방 참가자에게 실시간으로 공유되고, 참가자는 채팅으로 정답을 맞힙니다. 서버는 제시어, 제한 시간, 정답 판정, 점수 및 출제자 교대를 관리합니다.

## 구현 예정 기능

- 닉네임 등록 및 게임방 생성·입장·퇴장
- 그림판과 실시간 그림 공유
- 게임방별 채팅·이모티콘 및 정답 판정
- 라운드, 제한 시간, 점수 및 최종 순위
- 글자 수·초성 힌트와 재대결

## 1차 통신 규약 초안 (#1)

서버와 클라이언트가 접속, 게임방, 채팅을 연결할 때 사용하는 규약이다. 팀원과 합의한 뒤 확정한다.

- Java TCP 소켓을 사용한다. 기본 포트는 `5000`으로 제안한다.
- 모든 메시지는 UTF-8로 인코딩하고, 끝에 줄바꿈(`\n`)을 붙여 한 줄씩 전송한다.
- 첫 항목은 메시지 이름이고, 이후 항목은 `|`로 구분한다.
- 닉네임과 방 이름에는 `|`와 줄바꿈을 허용하지 않는다. 채팅 본문은 마지막 항목이므로 본문 속 `|`는 그대로 처리한다. 채팅도 한 줄씩 전송한다.
- 닉네임을 등록한 뒤 방을 이용할 수 있다. 한 사용자는 한 번에 한 방에 참가하고, 방 생성자는 만든 방에 자동으로 입장한다.
- 방 목록은 `방 ID`, `방 이름` 쌍을 반복해서 보낸다. 방이 없으면 `ROOMS`만 보낸다.

| 기능 | 프로토콜 | 프로토콜 형식 | 실제 예시 | 각 값의 의미 | 전송 방향 | 전송 시점 | 수신 후 처리 |
|---|---|---|---|---|---|---|---|
| 닉네임 등록 | `LOGIN` | `LOGIN\|<닉네임>` | `LOGIN\|그림왕` | 사용할 닉네임 | 클라이언트 → 서버 | 연결 후 닉네임 입력 시 | 서버가 중복을 확인하고 등록한다. |
| 등록 성공 | `LOGIN_OK` | `LOGIN_OK` | `LOGIN_OK` | 추가 값 없음 | 서버 → 요청자 | 닉네임 등록 완료 시 | 클라이언트가 대기실을 표시한다. |
| 방 목록 요청 | `LIST_ROOMS` | `LIST_ROOMS` | `LIST_ROOMS` | 추가 값 없음 | 클라이언트 → 서버 | 대기실 진입 또는 새로고침 시 | 서버가 현재 방 목록을 응답한다. |
| 방 목록 응답 | `ROOMS` | `ROOMS\|<방 ID>\|<방 이름>\|…` | `ROOMS\|1\|연습방\|2\|친구방` | 방 ID와 이름의 쌍 | 서버 → 요청자 | 목록 요청 처리 후 | 클라이언트가 방 목록을 갱신한다. |
| 방 생성 | `CREATE_ROOM` | `CREATE_ROOM\|<방 이름>` | `CREATE_ROOM\|연습방` | 새 방의 이름 | 클라이언트 → 서버 | 방 만들기 버튼을 눌렀을 때 | 서버가 방 ID를 배정하고 생성자를 입장시킨다. |
| 방 생성 성공 | `ROOM_CREATED` | `ROOM_CREATED\|<방 ID>` | `ROOM_CREATED\|1` | 생성된 방의 ID | 서버 → 생성자 | 방 생성 및 입장 완료 시 | 클라이언트가 해당 방 화면을 표시한다. |
| 방 입장 | `JOIN_ROOM` | `JOIN_ROOM\|<방 ID>` | `JOIN_ROOM\|1` | 입장할 방의 ID | 클라이언트 → 서버 | 목록에서 방 입장을 눌렀을 때 | 서버가 방을 확인하고 참가자로 등록한다. |
| 방 입장 성공 | `JOIN_OK` | `JOIN_OK\|<방 ID>` | `JOIN_OK\|1` | 입장한 방의 ID | 서버 → 요청자 | 입장 처리 완료 시 | 클라이언트가 해당 방 화면을 표시한다. |
| 방 퇴장 | `LEAVE_ROOM` | `LEAVE_ROOM` | `LEAVE_ROOM` | 현재 방에서 나간다는 요청 | 클라이언트 → 서버 | 나가기 버튼을 눌렀을 때 | 서버가 현재 방의 참가자 목록에서 제거한다. |
| 방 퇴장 성공 | `LEAVE_OK` | `LEAVE_OK` | `LEAVE_OK` | 추가 값 없음 | 서버 → 요청자 | 퇴장 처리 완료 시 | 클라이언트가 대기실로 돌아간다. |
| 참가자 목록 | `PLAYERS` | `PLAYERS\|<닉네임>\|…` | `PLAYERS\|그림왕\|스케치왕` | 현재 방의 참가자 닉네임 목록 | 서버 → 해당 방 참가자 | 방 생성, 입장, 퇴장 또는 연결 종료 후 | 클라이언트가 참가자 목록을 갱신한다. |
| 채팅 요청 | `CHAT` | `CHAT\|<본문>` | `CHAT\|안녕하세요` | 입력한 채팅 내용 | 클라이언트 → 서버 | 채팅을 보낼 때 | 서버가 송신자의 닉네임과 소속 방을 확인한다. |
| 채팅 전달 | `CHAT` | `CHAT\|<닉네임>\|<본문>` | `CHAT\|그림왕\|안녕하세요` | 보낸 사람의 닉네임과 내용 | 서버 → 같은 방 참가자 전체 | 채팅 요청 처리 후 | 클라이언트가 받은 메시지를 채팅창에 표시한다. |
| 오류 응답 | `ERROR` | `ERROR\|<오류 코드>` | `ERROR\|ROOM_NOT_FOUND` | 요청이 실패한 이유 | 서버 → 요청자 | 요청을 처리할 수 없을 때 | 클라이언트가 코드에 맞는 안내를 표시한다. |
| 대기실 접속자 목록 | `LOBBY_USERS` | `LOBBY_USERS\|<닉네임>\|…` | `LOBBY_USERS\|그림왕\|스케치왕` | 현재 대기실에 있는 사용자의 닉네임 목록 | 서버 → 대기실에 있는 클라이언트 전체 | 로그인 성공, 방 생성·입장·퇴장, 연결 종료로 대기실 인원이 바뀐 직후 | 클라이언트가 받은 닉네임 목록으로 대기실의 `JList`를 갱신한다. |
오류 코드는 닉네임 중복에 `NICKNAME_TAKEN`, 없는 방에 입장을 요청하면 `ROOM_NOT_FOUND`, 방에 들어가기 전에 채팅을 보내면 `NOT_IN_ROOM`을 사용한다.

### 대기실 접속자 목록 전송 순서

서버는 사용자 상태를 먼저 갱신한 뒤, 해당 요청의 성공 응답을 보내고 대기실에 있는 클라이언트 전체에 최신 `LOBBY_USERS` 목록을 전송한다.

1. **로그인 성공** — 사용자를 대기실에 추가한다. 로그인한 사용자에게 `LOGIN_OK`를 먼저 보내고, 새 사용자를 포함한 대기실 전체에 `LOBBY_USERS`를 보낸다.
2. **방 생성 또는 입장 성공** — 사용자를 대기실에서 빼고 해당 방에 추가한다. 요청자에게 `ROOM_CREATED|<방 ID>` 또는 `JOIN_OK|<방 ID>`를 보낸 뒤, 대기실에 남은 사용자들에게 `LOBBY_USERS`를 보낸다.
3. **방 퇴장 성공** — 사용자를 방에서 빼고 대기실에 추가한다. 퇴장한 사용자에게 `LEAVE_OK`를 먼저 보내고, 돌아온 사용자를 포함한 대기실 전체에 `LOBBY_USERS`를 보낸다.
4. **대기실 사용자 연결 종료** — 사용자를 대기실 목록에서 제거한 뒤, 남은 사용자들에게 `LOBBY_USERS`를 보낸다.

`ROOMS`는 `LIST_ROOMS`에 대한 응답이다. 클라이언트는 `ROOMS`와 `LOBBY_USERS`의 도착 순서에 관계없이 메시지 종류에 따라 방 목록과 접속자 목록을 각각 갱신한다.

## 첫 통합 테스트

1. 서버 하나에 클라이언트 두 개를 서로 다른 닉네임으로 연결한다.
2. 한 명이 방을 만들고 다른 한 명이 입장한다. 두 화면의 참가자 목록을 확인한다.
3. 한글 채팅을 보내고 두 화면에 같은 내용이 표시되는지 확인한다.
4. 한 명이 퇴장하면 남은 사람의 참가자 목록이 갱신되는지 확인한다.

그림 동기화, 제시어, 라운드, 정답 판정 및 점수 메시지는 해당 기능을 개발하기 전에 규약을 추가한다.
