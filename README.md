# 낙서한판

**팀 그려조**의 네트워크프로그래밍 텀프로젝트입니다.

낙서한판은 Java TCP 소켓과 Swing을 활용한 실시간 그림 퀴즈 게임입니다. 출제자가 그림을 그리면 같은 게임방 참가자에게 실시간으로 공유되고, 참가자는 채팅으로 정답을 맞힙니다. 서버는 제시어, 제한 시간, 정답 판정, 점수 및 출제자 교대를 관리합니다.

## 구현 예정 기능

- 닉네임 등록, 대기실 접속자 목록, 게임방 생성·입장·퇴장
- 그림판과 실시간 그림 공유
- 게임방별 채팅·이모티콘 및 정답 판정
- 라운드, 제한 시간, 점수 및 최종 순위
- 글자 수·초성 힌트와 재대결

## 1차 통신 규약 초안 (#1)

서버와 클라이언트가 접속, 게임방, 채팅을 연결할 때 사용하는 규약이다. 팀원과 합의한 뒤 확정한다.

- Java TCP 소켓을 사용한다. 기본 포트는 `5000`으로 제안한다.
- 모든 메시지는 UTF-8로 인코딩하고, 끝에 줄바꿈(`\n`)을 붙여 한 줄씩 전송한다.
- 첫 항목은 메시지 이름이고, 이후 항목은 `|`로 구분한다.
- 닉네임과 방 이름에는 `|`와 줄바꿈을 허용하지 않는다. 채팅 본문은 마지막 항목이므로 본문 속 `|`는 그대로 처리한다. 채팅도 한 줄씩 전송한다.
- 닉네임을 등록한 뒤 방을 이용할 수 있다. 한 사용자는 한 번에 한 방에 참가하고, 방 생성자는 만든 방에 자동으로 입장한다.
- 방 목록은 `방 ID`, `방 이름` 쌍을 반복해서 보낸다. 방이 없으면 `ROOMS`만 보낸다.

닉네임이 중복되면 `NICKNAME_TAKEN`, 존재하지 않는 방에 입장을 요청하면 `ROOM_NOT_FOUND`, 방에 들어가기 전에 채팅을 보내면 `NOT_IN_ROOM`을 사용한다.

일반 채팅은 요청과 전달 모두 `CHAT`을 사용한다. 서버 공지는 `CHAT_NOTIFY`를 사용하며, 클라이언트는 메시지 이름으로 일반 채팅과 공지를 구분한다. 닉네임이 `SYSTEM`인 사용자의 `CHAT` 메시지도 일반 채팅으로 표시한다.

채팅과 공지의 본문에는 `|`를 허용한다. 서버는 채팅 요청을 최대 2개 항목으로, 클라이언트는 채팅 전달을 최대 3개 항목으로, 서버 공지를 최대 2개 항목으로 나누어 처리한다.

### 대기실 접속자 목록 전송 순서

`LOBBY_USERS`에는 대기실에 있는 사용자의 닉네임을 모두 담는다. 목록을 받는 사용자 자신의 닉네임도 포함한다.

1. **로그인 성공** — 사용자를 대기실에 추가한다. 로그인한 사용자에게 `LOGIN_OK`를 먼저 보내고, 새 사용자를 포함한 대기실 전체에 `LOBBY_USERS`를 보낸다.
2. **방 생성 또는 입장 성공** — 사용자를 대기실에서 빼고 해당 방에 추가한다. 요청자에게 `ROOM_CREATED|<방 ID>` 또는 `JOIN_OK|<방 ID>`를 보낸 뒤, 대기실에 남은 사용자들에게 `LOBBY_USERS`를 보낸다.
3. **방 퇴장 성공** — 사용자를 방에서 빼고 대기실에 추가한다. 퇴장한 사용자에게 `LEAVE_OK`를 먼저 보내고, 돌아온 사용자를 포함한 대기실 전체에 `LOBBY_USERS`를 보낸다.
4. **대기실 사용자 연결 종료** — 사용자를 대기실 목록에서 제거한 뒤, 남은 사용자들에게 `LOBBY_USERS`를 보낸다.

`ROOMS`는 `LIST_ROOMS`에 대한 응답이다. 클라이언트는 `ROOMS`와 `LOBBY_USERS`의 도착 순서에 관계없이 메시지 종류에 따라 방 목록과 접속자 목록을 각각 갱신한다.

## 첫 통합 테스트

1. 서버 하나에 클라이언트 두 개를 서로 다른 닉네임으로 연결한다. 두 화면의 대기실 접속자 목록에 두 닉네임이 모두 표시되는지 확인한다.
2. 클라이언트 하나를 종료하고 남은 화면에서 종료한 사용자의 닉네임이 사라지는지 확인한 뒤, 종료한 클라이언트를 다시 연결한다.
3. 한 명이 방을 만든다. 대기실에 남은 사용자의 접속자 목록에서 방을 만든 사용자의 닉네임이 빠지는지 확인한다.
4. 대기실에 남은 사용자가 방 목록을 새로고침한 뒤 같은 방에 입장한다. 두 화면의 게임방 참가자 목록에 두 닉네임이 모두 표시되는지 확인한다.
5. 한글 채팅을 보내고 두 화면에 같은 내용이 표시되는지 확인한다.
6. 한 명이 퇴장한다. 방에 남은 사용자의 참가자 목록이 갱신되고, 퇴장한 사용자의 닉네임이 대기실 접속자 목록에 표시되는지 확인한다.

## 핵심 게임 진행 규칙 및 통신 규약 (#19)

### 게임 진행 규칙

| 항목 | 규칙 |
|---|---|
| 게임 시작 | 대기 중인 방에 참가자가 3명 이상일 때 방장만 게임을 시작할 수 있다. 한 방에는 출제자를 포함해 최대 4명이 참가한다. |
| 라운드 | 한 라운드에는 출제자 한 명과 제시어 하나가 배정된다. 참가 인원과 관계없이 12라운드를 완료하면 게임이 끝난다. |
| 출제 순서 | 첫 출제자는 가장 먼저 입장한 참가자다. 이후에는 직전 출제자의 입장 순번 뒤에 있는 참가자 중 가장 앞선 사람에게 넘긴다. 해당 순번 뒤에 남은 참가자가 없으면 목록의 처음으로 돌아간다. |
| 제시어 | 서버는 한글 단어 목록에서 같은 게임 안에서 중복 없이 제시어를 선택한다. 출제자에게만 단어를 보내고, 다른 참가자에게는 한글 음절 수를 보낸다. 취소된 라운드를 다시 시작할 때도 새 단어를 사용한다. |
| 제한 시간 | 라운드마다 140초를 부여한다. 서버가 남은 시간과 정답 입력 마감 여부를 판단한다. |
| 정답 판정 | 출제자를 제외한 참가자의 채팅에서 앞뒤 공백을 제거한 값이 제시어와 일치하면 정답으로 처리한다. 한 참가자는 한 라운드에 한 번만 정답 점수를 받는다. |
| 점수 | 서버가 정답으로 판정한 순서대로 1등 100점, 2등 80점, 3등 60점을 부여한다. 출제자는 정답자 1명당 20점을 받는다. |
| 정답 알림 | 정답자의 닉네임·순위·획득 점수를 같은 방에 알린다. 출제자나 이미 정답을 맞힌 참가자가 입력한 경우를 포함해, 제시어와 일치한 채팅 본문은 라운드 진행 중 일반 채팅으로 전달하지 않는다. |
| 라운드 종료 | 남아 있는 정답 참가자가 모두 맞히거나 제한 시간이 끝나면 제시어를 공개한다. 1~11라운드는 3초 뒤 다음 라운드를 시작하고, 12라운드는 제시어 공개 직후 최종 결과를 전송한다. |
| 최종 순위 | 방에 남아 있는 참가자를 점수 내림차순으로 정렬한다. 동점자는 같은 순위를 부여하고 입장 순서대로 표시한다. 예를 들어 100·100·80·80점이면 공동 1위·공동 1위·공동 3위·공동 3위로 표시한다. |

### 방 상태와 방장 위임

| 상태 | 처리 |
|---|---|
| `WAITING` | 최대 4명까지 입장할 수 있다. 3명 이상이면 방장의 시작 버튼을 활성화한다. |
| `PLAYING` | 새 참가자의 입장을 거절한다. 현재 출제자만 그릴 수 있고, 서버가 타이머와 정답 판정을 처리한다. |
| `ROUND_TRANSITION` | 정답 공개 또는 출제자 교대 안내를 표시한다. 입장·그리기·정답 판정을 중지한다. |

- 서버는 `Room`의 `players`를 입장이 완료된 순서대로 관리한다. 첫 번째 참가자가 방장이다.
- 방장이 `LEAVE_ROOM`을 보내거나 연결을 종료하면, 남은 참가자 중 가장 먼저 입장한 사람에게 방장 권한을 위임한다.
- 서버는 참가자 목록이 바뀌면 `PLAYERS|<닉네임1>|<닉네임2>|…`를 같은 방 전체에 보낸다. 방장이 변경되면 이어서 `CHAT_NOTIFY|<새 방장 닉네임>님이 새로운 방장이 되었습니다.`를 전송한다.
- 클라이언트는 `PLAYERS`의 첫 번째 닉네임을 방장으로 표시한다. `PLAYERS`, `GAME_STARTED`, `GAME_END`를 수신하면 방장 여부·참가 인원·방 상태를 기준으로 게임 시작 버튼을 갱신한다.
- 방장과 출제자는 별도 역할이다. 방장이 퇴장해도 현재 출제자가 남아 있고 참가자가 3명 이상이면 라운드를 이어간다.

### 참가자 퇴장 처리 우선순위

1. 퇴장한 참가자를 목록에서 제거한다. 방장이 나갔다면 남은 참가자의 입장 순서에 따라 새 방장을 선정한다.
2. 참가자가 0명이면 타이머와 예약 작업을 취소하고 방을 삭제한다.
3. 방이 유지되면 `PLAYERS`, 방장 변경 공지(해당 시), 퇴장 공지 순서로 같은 방에 전송한다.
4. 게임 진행 또는 전환 대기 중 **2명 이하**가 되면 인원 부족 종료를 우선한다. 남은 참가자의 점수를 0점으로 초기화한 뒤 `SCORES` → `GAME_END|NOT_ENOUGH_PLAYERS`를 전송한다.
5. **3명 이상 남은 상태에서 진행 중인 출제자가 나가면** 현재 라운드를 취소한다. 남은 참가자의 점수를 라운드 시작 시점으로 복원하고 `ROUND_CANCEL` → `SCORES`를 보낸다. 클라이언트는 그림판에 출제자 퇴장과 3초 대기를 안내한다. 3초 후 인원과 방 상태를 다시 확인하고, 다음 출제자와 새 제시어를 배정해 같은 라운드 번호에서 다시 시작한다. 취소된 라운드는 완료 횟수에 포함하지 않는다.
6. **3명 이상 남고 출제자가 유지되면** 라운드를 이어간다. 퇴장자의 점수는 현재 참가자 점수표에서 제거한다. 이미 인정한 정답 순서와 출제자 보너스는 유지하며, 남은 정답 참가자가 모두 맞혔는지 다시 확인한다.
7. 정상 종료 후 3초 전환 대기 중에 직전 출제자가 나가더라도 해당 라운드의 점수와 완료 횟수를 유지한다. 전환 대기 중 2명 이하가 되면 예약된 라운드 시작을 취소한다.

### 게임 종료와 초기화

| 상황 | 처리 |
|---|---|
| 12라운드 정상 종료 | 마지막 제시어와 최종 점수·공동순위를 표시하고, 같은 방의 대기 상태로 돌아간다. 점수표에는 다음 게임을 시작할 때까지 최종 점수를 유지한다. |
| 다음 게임 시작 | 참가자 점수를 0점으로 초기화하고 1라운드·빈 그림판·새 제시어·140초에서 시작한다. |
| 인원 부족 종료 | “참가자가 2명 이하가 되어 이번 게임을 종료합니다.”라는 안내를 표시한다. 그림판과 점수를 초기화하고 같은 방의 대기 상태로 돌아간다. |
| 공통 처리 | 서버는 타이머와 예약된 라운드 전환을 취소한다. 클라이언트는 남은 시간·제시어·힌트·출제자 표시를 초기화하고 그리기 권한을 해제한다. 대기 상태로 돌아온 방에는 입장 및 게임 시작 조건을 다시 적용한다. |

### 게임 시작·라운드·점수 메시지

기존과 동일하게 UTF-8을 사용한다. 메시지는 `|`로 항목을 구분하고, 끝에 줄바꿈(`\n`)을 붙인다. 일반 채팅은 `CHAT`, 서버 공지는 `CHAT_NOTIFY`를 사용한다. 초성 힌트의 메시지 형식은 해당 기능을 구현할 때 별도로 정한다.

`roundNo`는 화면에 표시하는 1~12 사이의 번호다. `roundId`는 서버가 같은 방에서 라운드를 시작할 때마다 증가시키는 식별자다. 같은 라운드를 재시작하거나 새 게임을 시작할 때도 새로운 `roundId`를 사용한다.

| 기능 | 전송 대상 | 형식 | 전송 시점과 수신 후 처리 |
|---|---|---|---|
| 게임 시작 요청 | 클라이언트 → 서버 | `START_GAME` | 방장이 시작 버튼을 누르면 전송한다. 서버는 방 소속, 방장 권한, 대기 상태, 최소 인원을 확인한다. |
| 게임 시작 승인 | 서버 → 같은 방 전체 | `GAME_STARTED\|12` | 시작이 승인되면 전송한다. 클라이언트는 전체 라운드 수를 저장하고 시작 버튼을 비활성화한다. |
| 라운드 시작 | 서버 → 같은 방 전체 | `ROUND_START\|<roundId>\|<roundNo>\|<출제자>\|140` | 새 라운드 또는 취소된 라운드의 재시작 시 전송한다. 클라이언트는 그림판과 이전 라운드 표시를 초기화하고 출제자·라운드 번호·제한 시간을 설정한다. |
| 출제자용 제시어 | 서버 → 현재 출제자 | `WORD\|<roundId>\|<제시어>` | `CLEAR_NOTIFY` 전송 후 출제자에게 보낸다. 출제자 화면에 제시어를 표시한다. |
| 참가자용 글자 수 | 서버 → 출제자 외 참가자 | `WORD_LENGTH\|<roundId>\|<글자 수>` | `CLEAR_NOTIFY` 전송 후 출제자를 제외한 참가자에게 보낸다. 참가자 화면에 글자 수를 표시한다. |
| 남은 시간 | 서버 → 같은 방 전체 | `ROUND_TIME\|<roundId>\|<남은 초>` | 제시어와 글자 수를 각 대상에게 보낸 뒤 초기 140초를 전송하고, 이후 남은 초가 바뀔 때마다 전송한다. 클라이언트는 시간과 진행 막대를 갱신한다. |
| 정답 알림 | 서버 → 같은 방 전체 | `CORRECT_NOTIFY\|<roundId>\|<닉네임>\|<정답 순위>\|<획득 점수>` | 각 참가자의 정답을 처음 인정할 때 보낸다. 화면에는 닉네임·순위·획득 점수를 표시한다. |
| 현재 점수 | 서버 → 같은 방 전체 | `SCORES\|<닉네임>\|<누적 점수>\|…` | 게임 시작, 정답 인정, 참가자 변경, 점수 복원·초기화 후에 보낸다. 현재 참가자의 닉네임과 점수 쌍을 입장 순서대로 보내고, 클라이언트는 점수표를 갱신한다. |
| 라운드 종료 | 서버 → 같은 방 전체 | `ROUND_END\|<roundId>\|<종료 사유>\|<제시어>` | 전원 정답이면 `ALL_CORRECT`, 시간 초과면 `TIMEOUT`을 보낸다. 제시어를 공개하고 그리기와 정답 판정을 중지한다. |
| 라운드 취소 | 서버 → 같은 방 전체 | `ROUND_CANCEL\|<roundId>\|DRAWER_LEFT\|3` | 진행 중인 출제자가 퇴장하고 3명 이상 남았을 때 보낸다. 그림판에 3초 전환 안내를 표시한다. |
| 게임 정상 종료 | 서버 → 같은 방 전체 | `GAME_END\|COMPLETED\|<닉네임>\|<최종 점수>\|<순위>\|…` | 12라운드 종료 시 닉네임·점수·순위를 한 묶음으로 보낸다. 클라이언트는 최종 결과를 표시하고 대기 상태로 돌아간다. |
| 인원 부족 종료 | 서버 → 같은 방 전체 | `GAME_END\|NOT_ENOUGH_PLAYERS` | 진행 중 또는 전환 대기 중 2명 이하가 됐을 때 보낸다. 클라이언트는 종료를 알리고 대기 상태로 돌아간다. |

### 오류 응답

서버는 요청자에게 `ERROR|<오류 코드>`를 보낸다. 방 입장 요청은 방 존재 여부 → 대기 상태 여부 → 정원 순서로 검사한다.

| 오류 코드 | 적용 기준 |
|---|---|
| `ROOM_NOT_FOUND` | 존재하지 않는 방에 입장을 요청했다. |
| `NOT_IN_ROOM` | 방에 속하지 않은 상태에서 게임 시작 또는 그림을 요청했다. |
| `NOT_HOST` | 방장 권한 없이 게임 시작을 요청했다. |
| `NOT_ENOUGH_PLAYERS` | 방장이 대기 상태에서 시작을 요청했지만 참가자가 3명 미만이다. |
| `GAME_IN_PROGRESS` | 진행 중 또는 전환 대기 중인 방에 시작이나 입장을 요청했다. |
| `ROOM_FULL` | 대기 중인 방에 이미 4명이 참가하고 있다. |
| `ROUND_NOT_ACTIVE` | 진행 중인 라운드가 없거나 그림 요청의 `roundId`가 현재 라운드와 다르다. |
| `NOT_DRAWER` | 현재 출제자의 권한 없이 현재 라운드의 그림을 요청했다. |
| `INVALID_DRAW_REQUEST` | 필수 항목이 빠졌거나 `roundId`·좌표·색상·굵기 형식 또는 값이 잘못됐다. |

### 그림 동기화

- 그림판의 기준 크기는 `800 × 500`이며 정수 좌표 범위는 `x = 0~799`, `y = 0~499`다. 화면에 표시할 때 좌표와 선 굵기에 같은 배율을 적용하고, 남는 공간은 여백으로 둔다.
- 기본 펜 색상은 검정이다. 펜은 아래 순서의 9가지 색상과 기준 굵기 `2`, `4`, `8`을 사용한다. 흰색 펜에도 선택한 굵기를 적용한다.
- 그림판 배경은 흰색이다. 지우개는 `#FFFFFF`와 굵기 `16`을 `DRAW`로 전송한다. 서버는 9가지 펜 색상과 굵기 `2`, `4`, `8`의 조합 및 지우개 조합을 허용한다.

| 색상 | 전송 값 |
|---|---|
| 빨강 | `#FF0000` |
| 주황 | `#FFA500` |
| 노랑 | `#FFFF00` |
| 초록 | `#008000` |
| 파랑 | `#0000FF` |
| 남색 | `#000080` |
| 보라 | `#800080` |
| 흰색 | `#FFFFFF` |
| 검정 | `#000000` |

| 기능 | 전송 대상 | 형식 |
|---|---|---|
| 선분 요청 | 클라이언트 → 서버 | `DRAW\|<roundId>\|<x1>\|<y1>\|<x2>\|<y2>\|<색상>\|<굵기>` |
| 선분 전달 | 서버 → 보낸 사람을 포함한 같은 방 전체 | `DRAW_NOTIFY\|<roundId>\|<x1>\|<y1>\|<x2>\|<y2>\|<색상>\|<굵기>` |
| 전체 지우기 요청 | 클라이언트 → 서버 | `CLEAR\|<roundId>` |
| 전체 지우기 전달 | 서버 → 보낸 사람을 포함한 같은 방 전체 | `CLEAR_NOTIFY\|<roundId>` |

- 서버는 방 소속·진행 상태·`roundId`·출제자 권한·요청값을 확인한다. `roundId`가 빠졌거나 정수로 해석할 수 없으면 `ERROR|INVALID_DRAW_REQUEST`를 반환한다.
- 출제자 자신의 화면도 `DRAW_NOTIFY`를 받은 뒤 선분을 표시한다. 전체 지우기는 `CLEAR_NOTIFY`를 받은 뒤 적용한다. 수신 메시지는 화면에만 반영한다.
- 클라이언트는 현재 `roundId`에 해당하는 그림 변경을 수신 순서대로 Swing EDT에서 처리한다. `ROUND_START`를 받으면 그림판을 초기화한다. 서버는 `ROUND_START`에 이어 `CLEAR_NOTIFY`를 전송한다.
- 같은 TCP 연결의 그림·채팅·전체 지우기 요청은 공통 전송 큐에 넣고 순서대로 보낸다.

### 메시지 전송 순서

`WORD`는 출제자에게, `WORD_LENGTH`는 나머지 참가자에게 각각 전송한다. 방장 변경 공지와 퇴장 공지에는 `CHAT_NOTIFY`를 사용한다.

```text
게임 시작        GAME_STARTED → SCORES(전원 0점) → ROUND_START → CLEAR_NOTIFY → WORD 또는 WORD_LENGTH → ROUND_TIME(140초)
정답 인정        CORRECT_NOTIFY → SCORES → 전원 정답이면 ROUND_END(ALL_CORRECT)
시간 초과        ROUND_TIME(0) → ROUND_END(TIMEOUT)
정상 라운드 전환 ROUND_END → 3초 대기 → ROUND_START → CLEAR_NOTIFY → WORD 또는 WORD_LENGTH → ROUND_TIME(140초)
출제자 퇴장      PLAYERS → 방장 변경 공지(해당 시) → 퇴장 공지 → ROUND_CANCEL → SCORES(복원) → 3초 대기 → 같은 라운드 번호로 ROUND_START → CLEAR_NOTIFY → WORD 또는 WORD_LENGTH → ROUND_TIME(140초)
인원 부족 종료   PLAYERS → 방장 변경 공지(해당 시) → 퇴장 공지 → SCORES(전원 0점) → GAME_END(NOT_ENOUGH_PLAYERS)
12라운드 완료    ROUND_END → GAME_END(COMPLETED)
```

- 서버는 방 단위로 입장·퇴장·정답·타임아웃·그림 요청을 순서대로 처리하고, 같은 연결로 전달되는 메시지 순서를 유지한다.
- 정답은 서버가 정한 마감 시각 전까지만 인정한다. 마지막 정답과 타임아웃이 겹쳐도 `ROUND_END`는 한 번만 보낸다.
- 서버는 예약된 타이머와 전환 작업을 실행하기 전에 대상 `roundId`, 방 상태, 참가 인원을 다시 확인한다. 취소되거나 이미 끝난 라운드의 예약 작업으로 다음 라운드가 중복 시작되는 것을 막는다.
